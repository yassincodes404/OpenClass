## Status Classification Legend

Every capability in OpenClass is classified into one of eight rigorous engineering states:

1. **Implemented and verified** — Real production code in `packages/`/`providers/`/`apps/` with automated tests verifying true invariants.
2. **Implemented but unverified** — Code exists in production packages but lacks automated tests or is only covered by mocked/shortcut tests.
3. **Partially implemented** — Core happy path exists, but critical parameters, error paths, persistence, or downstream layers are missing or broken.
4. **Experimental / research-only** — Working logic exists only in `scripts/` or `benchmarks/`, not integrated into `packages/core` or `packages/server`.
5. **Mock / simulated** — Behavior is backed by deterministic hashes, regexes, or hardcoded mock classes rather than real semantic/model execution.
6. **Documented but absent** — Described in `docs/`, `README.md`, or phase specs (`phase-11`..`20`), with zero implementation in the codebase.
7. **Blocked by another component** — Intentionally fail-closed (e.g., `HTTP 409 Conflict`) awaiting an upstream prerequisite.
8. **Obsolete or duplicated** — Competing implementations across Era 1, Era 2, and Era 3 that create split-brain state.
